# AI Gateway privacy notes

AI Gateway is a GPL-3.0 Android fork of v2rayNG. Its VPN service routes network connections through user-selected proxy servers or directly through the current network, according to local routing rules.

- Server profiles, subscriptions, settings and imported rules are stored on the device. Treat node links, credentials, QR codes and exported backups as sensitive.
- The gateway does not add an AI prompt collection service, TLS interception or a developer-operated traffic relay. Proxy operators, DNS operators and destination services may observe information appropriate to their roles.
- The default DNS providers inherited from v2rayNG are Cloudflare (`1.1.1.1`) for proxy DNS and Alibaba (`223.5.5.5`) for direct DNS. Users can change these addresses. Node hostname resolution and application-managed DNS may use different resolvers.
- Updating subscriptions validates authorization and downloads nodes from the operator's service embedded in the app build configuration. Legacy unmanaged subscriptions cannot refresh or start the gateway in this build. Geo-data downloads, connectivity/IP checks, update checks and links to GitHub or upstream community pages contact their respective services.
- Invitation redemption sends the entered code and a random retry identifier to the embedded invitation service. The customer screen only requests a code; it does not display or ask for an API address. Every gateway start and subscription update sends the subscription token for online authorization. An active gateway repeats validation every 60 seconds, with a 25-second request timeout. The operator sees request IP addresses and validation timing, manages invitation-to-node mappings, and can revoke authorization. These requests do not send browsing history or AI prompts. Only install builds from an operator you trust.
- Invitation retries keep a hash of the service/code and the random request identifier in app-private settings; the plaintext code is not persisted. The returned subscription token and node credentials are stored with the normal app configuration and can be included in user-initiated backups. Treat subscription URLs as passwords. Reinstalling or clearing app data loses the retry identifier; a consumed code then requires the operator to issue a replacement.
- Invitation requests require HTTPS in release builds and do not follow redirects. Debug builds additionally permit HTTP on loopback and the Android emulator host alias for local development. Authorization expiry stops this app's active gateway using a server-derived monotonic deadline; revocation or network failure stops it when validation next fails. There is no offline grace period. Revocation does not erase downloaded credentials: old, modified or third-party clients may still use shared nodes, so universal access revocation requires changes on the proxy server.
- Local logs may contain hostnames, addresses and connection errors. Review logs before sharing them.
- Optional WebDAV backups transfer configuration to the server selected by the user. Clipboard exports and file sharing are initiated by the user.
- Filtering is performed locally; importing a rule file does not upload it. AI rules and a pinned Loyalsoldier Geo dataset are bundled, so first use does not contact GitHub to fetch rules. User-initiated updates contact the selected GitHub repository or custom HTTPS source, through the local proxy when available with a direct retry if necessary.
- Uninstalling the app removes app-private configuration, but does not remove previously exported files, copies on remote backup services or third-party records.

This document describes this fork's changes and inherited network-facing features; it is not a promise of anonymous browsing or a no-leak guarantee. See the routing limitations in [README.md](README.md).
